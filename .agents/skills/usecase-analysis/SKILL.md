# PM4Py でイベントログを分析する

ケース ID・アクティビティ・時刻の3列があるログから、観測された流れをまとめる。対象プロダクトの仕様や列の意味はスキルに含めない。ログとユーザーの説明だけを根拠にする。

## スクリプト

分析はこのスキルの `scripts/analyze_event_log.py` を実行する。対象リポジトリへコピーしない。処理を書き直さない。`pm4py.discover_performance_dfg` は呼ばない。繰り返しの畳み込みを自前の全探索にしない。

```sh
SCRIPT="<この SKILL.md と同じディレクトリ>/scripts/analyze_event_log.py"
VENV="${PM4PY_VENV:-$HOME/.cache/pm4py-venv}"
if [ ! -x "$VENV/bin/python" ]; then
  python3 -m venv "$VENV"
  "$VENV/bin/pip" install -q pm4py
fi
"$VENV/bin/python" -u "$SCRIPT" LOG.csv
```

仮想環境はリポジトリの外に作る。システム Python へは入れない。PM4Py は AGPL-3.0 なので、対象プロジェクトの依存関係に追加しない。

数十万行なら数秒から十数秒で `DONE` まで出る。出力が止まったまま 1 分を超えたら、このスクリプト以外の処理が混ざっていないか確認して止める。

## 引数

列名は指定が無ければ次の候補から選ぶ。`case:concept:name` / `case_id` / `caseid` / `case`、`concept:name` / `activity` / `activity_name` / `event`、`time:timestamp` / `timestamp` / `time` / `event_time`。

| 引数 | 意味 |
|---|---|
| `--case` `--activity` `--timestamp` | 列名が候補と違うとき |
| `--group COL` | この列の値ごとに同じ分析を繰り返す。指定しなければログ全体を 1 本にする |
| `--min-coverage 0.05` | これ未満の直接後続は、件数上位でなければ省く |
| `--top-edges 40` | 表示する直接後続の上限 |
| `--top-variants 12` | 表示するバリアントの上限 |

時刻は ISO-8601 を先に解釈し、ダメなら pandas の推定に落とす。読めない行は落として件数を出す。

## スクリプトがやっていること

アクティビティ名はそのまま出す。短縮や分類はしない。

1. ケースと時刻で安定ソートする。
2. `pm4py.discover_dfg` で開始と終了の件数を取る。
3. 同一ケースで連続する同じアクティビティを先頭の 1 件に畳む。ポーリングや再試行の自己ループを 1 ステップにする。
4. 畳んだログでもう一度 `discover_dfg` する。エッジを通ったケースの割合と、所要時間の中央値は pandas で計算する。中央値は畳んだ先頭の時刻から次の別アクティビティまでなので、繰り返していた時間を含む。
5. `pm4py.get_variants(..., max_repetitions=1)` のあと、周期 2〜6 の隣接繰り返しを最大 8 パスで `(A -> B)×k` に畳む。
6. 畳む前のログで、ケースあたりのイベント数、アクティビティ回数の分位点、ケースの長さを出す。回数の分位点は 0 回のケースを含む。半数未満にしか現れないアクティビティの中央値は 0 になる。`with` が 1 回でも含むケース数。

## 報告

チャットに書く。ファイルへ残すのはユーザーが求めたときだけ。数値はスクリプト出力以外を使わない。観測していない行為は書かない。

この順で書く。

1. 期間、イベント数、ケース数。グループ分けたならその内訳。イベント数の多いアクティビティと、それが全体に占める割合。
2. 開始と終了。開始が分かれるとき、少ない側は観測窓の前から続いていた可能性がある、と可能性として書く。終了は窓の最後のイベントであり、窓の終わりで打ち切られた可能性がある。
3. ケース網羅率の高い直接後続を、中央値つきで流れとして書く。網羅率はケースの割合、follows はイベント回数である。
4. ケースあたりの回数と長さ（中央値、90%点、最大、1 回でも含むケース数）。
5. バリアント数と最頻の中身。上位を足しても覆えないときは、高網羅率のエッジが一つの流れかを見て、「流れは同じで回数だけ違う」のか「流れ自体が分かれる」のかを区別する。

アクティビティ名からドメインを言い換えてよい。会話に無い仕様を補って、遷移以上の意味を足さない。
